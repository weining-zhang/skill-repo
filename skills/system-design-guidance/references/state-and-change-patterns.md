# 状态与变化条件模式

当系统涉及持久状态、缓存、同步、更新、删除、迁移、重启恢复或身份切换时读取。以下是评审模式，不是无条件实现要求；使用前必须说明前提和例外。

## 事实、派生状态与执行快照

同一业务可能同时存在远端事实、本地持久状态、内存投影、缓存和单次执行快照。

- 为每类状态指定事实来源、owner、有效范围和失效条件。
- 在任务开始时冻结影响本次执行的身份和配置，避免全局更新改变在途行为。
- 禁止让内存投影或旧缓存反向定义权威事实。
- 区分“未就绪、空集合、请求失败、损坏和已删除”。

评审重点：全局更新影响在途任务还是仅影响后续任务；旧任务是否会把冻结值写回当前状态。

## 分层就绪

不要默认“资源存在”就等于“业务可用”。按领域需要区分：

```text
已获得 -> 前置条件已准备 -> 可发现 / 可见 -> 可执行
```

只有真正需要的阶段才建模。状态字段表达生命周期，失败原因单独记录。对外暴露在哪一层，必须与调用方契约一致。

## 期望状态与实际状态

事件或轮询只说明“可能发生变化”。需要长期收敛时：

- 定义 desired state、actual state 和比较规则。
- 保证收敛操作幂等。
- 删除依赖 tombstone、删除版本或等价权威事实。
- 不把分页、过滤、请求失败或暂时缺失误判为删除。
- 部分失败不推进会跳过未完成工作的成功水位。

只有在系统确实需要持续收敛时才引入 reconciler；不要为一次性局部操作增加常驻状态机。

## Last Known Good 与原子切换

新配置、新版本或新资源尚未完整成功时，可以保留上一份已验证状态：

- 在隔离位置准备新状态。
- 完成下载、校验、依赖和持久化后再切换。
- 失败尝试单独记录，不覆盖完整 ready 状态。
- 运行中读者固定自己开始时的版本或快照。

例外：旧状态已被安全撤销、违反权限或继续使用会损坏数据时，不得为了可用性保留 Last Known Good，应使用 Fail-closed 或受控降级。

## 所有权、代际与迟到写回

Promise、超时或布尔锁不能单独证明任务仍有写回资格。

- 为资源或执行上下文定义 revision、generation、epoch、attempt owner 或等价身份。
- 去重身份包含会改变结果语义的资源、版本、账号、租户或环境。
- 提交结果前重新校验 owner 和上下文是否仍有效。
- 用户的新操作、账号切换或新版本切换应明确夺取或替换旧任务的提交权。

实现可以使用 CAS、串行队列、资源锁或事务，但必须先定义语义。

## 取消与超时

分别回答：

- 取消的是某个等待者，还是共享工作？
- 底层操作能否真实取消？
- 不能取消时，如何撤销旧任务的提交权？
- 超时后任务和资源锁何时才算真正结束？
- 重试是否会与旧任务并行操作同一资源？

取消信号可以向下传播，但不能假设所有外部系统都支持取消。最终写回资格校验是独立保护。

## 按后果选择失败策略

| 场景 | 候选策略 | 约束 |
| --- | --- | --- |
| 推荐、提示、非关键诊断 | Fail-open | 失败不得改变主业务结果 |
| 权限、计费、安全、数据完整性 | Fail-closed | 缺少关键上下文时停止副作用 |
| 配置或版本更新 | Last Known Good | 旧状态必须仍然安全且兼容 |
| 删除或覆盖 | 无权威事实则保留 | 必须有明确删除依据 |
| 临时网络或资源占用 | 有限重试 | 退避、上限、幂等和放大成本明确 |
| 声明、格式或策略错误 | 停止自动重试 | 暴露可诊断原因和修复入口 |

不要让一批成功清除另一失败类别的恢复状态。

## 持久化可信度与恢复

- 写入需要防止部分状态被当成完整快照。
- 读取失败时区分暂时不可见、格式损坏、版本不兼容和真实空状态。
- 无法获得可信快照时显式失败，避免错误删除或覆盖。
- 事件到达时可以即时补偿；仍需说明错过事件、进程退出或重启后的恢复入口。
- 周期兜底、启动恢复和人工重试都是候选手段，按成本和恢复时限选择。

## 四层兼容性

- Wire：旧端能否解析和发送字段。
- 行为：同一操作的作用范围和默认行为是否改变。
- 持久化：旧记录能否被新版恢复和迁移。
- 降级：任一端版本较低时是否误执行、误授权或损坏状态。

验证兼容性时覆盖真实操作结果，不只验证序列化成功。
