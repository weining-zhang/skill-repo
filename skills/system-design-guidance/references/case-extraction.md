# 从补丁案例提炼设计模式

本参考只用于事后反推模式。目标不是复盘某个领域，而是从真实补丁中提炼可用于后续设计指导、方案 Review 和实现 Review 的条件模式。

## 输入证据

优先读取：

- 第一版实现和后续修复的 commit range。
- issue、事故、回归测试和失败日志。
- 当前代码中的真实状态、调用链和最终副作用。
- 已有设计文档与实现偏差。

重新验证仓库、分支、HEAD 和工作区状态。案例文档只能作为定位线索，不能替代当前代码事实。

## 提炼步骤

1. 区分功能扩展、普通缺陷和修复性补丁。
2. 按六个风险面归类补丁，不按文件目录归类。
3. 找出多个补丁是否反复跨越同一未命名边界。
4. 重建触发到最终副作用的流程线。
5. 识别最初缺失的决策、不变量或验证路径。
6. 把具体实现改写成条件模式，补充适用前提和反例。
7. 判断模式应进入主流程、条件 reference，还是仅保留为案例。

## 晋升规则

满足以下条件才把经验写入通用 Skill：

- 能脱离原项目名、接口名、目录名和状态名表达。
- 能说明适用前提、反例和代价。
- 能落到流程线、决策点和可验证不变量。
- 已在多个不同领域案例中重复出现，或属于明显的安全、数据完整性和最终副作用约束。

具体 timeout、重试次数、并发数、包管理器、IPC 方法和目录结构只保留为案例参数。

## 反哺验证

用新需求做前向验证：

1. 在方案形成或编码前运行 Skill 并保存关键决策和不变量。
2. 实现后对照 code review、回归测试和后续补丁。
3. 记录哪些风险被提前命中、哪些建议没有改变实现、哪些问题被遗漏。
4. 只根据重复证据调整风险面、流程模板或条件模式。

不要用单一案例无限扩充主 Skill。高频但场景受限的经验应留在 reference。
