# 六个一级风险面

使用本参考对 Deep 系统设计分析或评审做风险归类。六个面覆盖的是不同作用力，不代表必须平均展开。先找证据，再选择需要下钻的面。

## 目录

- 选择原则
- 事实与状态
- 时间与生命周期
- 边界与上下文
- 副作用与失败安全
- 性能与规模
- 演进与运行保障

## 选择原则

按以下因素排序：

- 影响：错误是否改变业务结果、数据、权限或可用性。
- 未知：关键行为是否依赖尚未确认的假设或外部契约。
- 不可逆性：失败后是否能自动恢复、人工恢复或可靠回滚。
- 影响范围：单请求、单用户、单租户、单设备、全量客户端或共享基础设施。

没有证据的问题不升级为阻塞项。无法确认但会改变实现边界的问题，标记为“需要外部确认”。

## 1. 事实与状态

关注事实从哪里来、如何派生、何时冻结，以及谁可以改变它。

重点检查：

- 区分权威事实、持久状态、内存投影、缓存和单次执行快照。
- 区分不存在、未就绪、空集合、读取失败、损坏和已删除。
- 明确状态 owner、写入者、读取者、版本或 revision。
- 明确期望状态与实际状态如何比较和收敛。
- 明确“存在、可见、可用、可执行”是否为不同阶段。
- 确认仅凭持久记录能否恢复业务含义。

常见补丁信号：把缓存当事实源、把读取失败当空数据、状态布尔化、旧快照覆盖新状态、部分成功推进完整水位。

## 2. 时间与生命周期

关注同一对象如何创建、变化、并发、失效、恢复和退出。

重点检查：

- 列出创建、就绪、使用、更新、切换、取消、失败、恢复、删除和回收。
- 找出跨 `await`、定时器、后台任务、事件回调和进程重启的状态。
- 明确重复触发是复用、合并、覆盖、排队还是拒绝。
- 明确乱序完成和迟到结果的提交资格。
- 区分调用方超时、等待者取消、底层工作取消和写回权失效。
- 明确错过事件或重启后如何恢复，不默认事件一定到达。

常见补丁信号：只有 happy path、用布尔锁代替所有权、超时后旧任务继续提交、切换身份后旧回调复活。

## 3. 边界与上下文

关注职责、身份、作用域和契约跨边界后是否仍保持原语义。

重点检查：

- 明确领域 owner、能力提供方、适配层和最终调用方的职责。
- 明确账号、租户、环境、请求、任务和进程作用域。
- 冻结并传播影响权限、计费、模型、运行时或资源选择的执行上下文。
- 在适配层统一主通道和 fallback 的状态码、错误、编码、取消及二进制语义。
- 明确外部 API 的受理、排队、执行和完成语义。
- 在信任边界检查认证、授权、隐私、输入和输出约束。

常见补丁信号：依赖“最近一次使用”的全局状态、adapter 泄漏宿主 DTO、fallback 只保证调用成功但数据语义不同、默认值掩盖关键身份缺失。

## 4. 副作用与失败安全

关注最终网络、数据库、文件、进程或用户可见结果是否在正确条件下发生。

重点检查：

- 找到最后一个仍可改变关键字段或状态的边界。
- 在最终副作用前校验关键不变量、身份和提交资格。
- 区分可重试、需人工处理、永久失败和未知结果。
- 按后果选择 Fail-open、Fail-closed、保留 Last Known Good 或停止操作。
- 删除和覆盖要求明确权威依据；缺失、过滤或分页不完整不自动等于删除。
- 明确原子提交、局部失败、补偿、回滚和人工恢复策略。

常见补丁信号：中间对象正确但最终请求错误、失败尝试覆盖可用状态、无删除事实却清理资源、所有错误使用同一重试策略。

## 5. 性能与规模

关注系统正确运行时是否仍会阻塞关键路径、争抢资源或在规模下放大成本。

重点检查：

- 明确优化目标是首次可交互、首次任务、最终就绪、吞吐还是资源峰值。
- 区分前台关键工作、后台最终完成工作和可放弃工作。
- 明确后台工作的准入、并发、时间、CPU、I/O、网络和磁盘预算。
- 评估重复触发、轮询、重试、Trace 和客户端同时启动的放大倍数。
- 区分业务逻辑归因和共享资源的物理成本去重。
- 检查平均值是否掩盖 P95/P99、低配设备或冷启动问题。

常见补丁信号：固定延迟代替就绪信号、后台观测阻塞主链路、单机正确但形成请求洪峰、优化总耗时却恶化首次任务。

## 6. 演进与运行保障

关注系统如何跨版本变化、受控发布、被观测并在异常时退出。

重点检查：

- 分别检查 wire、行为、持久化和降级兼容性。
- 明确旧数据迁移、版本切换、回滚和双版本共存策略。
- 明确灰度范围、功能开关、停止条件和 kill switch。
- 定义业务成功口径：对象、阶段、分母、终态、排除项和缺失样本。
- 区分 KPI 事件、诊断日志、Trace 和必须可靠的审计记录。
- 确保日志能关联 operation、resource identity、revision、触发源、失败阶段和最终结果。

常见补丁信号：只验证 JSON 可解析、旧操作作用域被隐式改变、指标先埋点后定义、诊断成功率被当作业务成功率、无法定位哪一代任务提交了结果。
